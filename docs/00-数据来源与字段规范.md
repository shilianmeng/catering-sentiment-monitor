# 数据来源与字段规范（v2.2，2026-11-24）

> 第三、五节是数据接入规范；第六、七节记录当前实现和演示基线。不能把规范中规划的字段或处理当作已实现功能。
> 一句话原则：**只采公开的、能给出处的东西；出处给不出的，不进系统。**

## 一、三类来源，规矩完全不同

| 来源类别 | 包含什么 | 能不能自己采 | 系统里怎么处理 |
|---|---|---|---|
| 官方通报 | 市场监管处罚公示、食品抽检不合格通报、信用中国/企业信用信息公示、裁判文书与法院公告 | **可以**，属于行政机关主动公开的信息 | 体检报告的主要数据来源；每条必须带官方链接 |
| 媒体报道 | 新闻门户、主流媒体的报道 | **可以采，但只存元数据**（标题、媒体、日期、原文链接、摘要） | 不存全文、不二次发布；报告里只引必要长度 |
| 顾客投诉 | 点评、美团、黑猫等平台的用户评论 | **不自己采** | 只走两条路：客户授权导出，或向平台/数据商采购 |

三条不能碰的红线：

1. **平台评论不爬。** 用户协议明确禁止，反不正当竞争已有判例（大众点评诉百度），还有非法获取数据的刑事风险。
2. **不存媒体全文。** 抓取争议不大，风险在于把全文落库后再复用——那是著作权问题。
3. **投诉内容不算事实。** 是消费者单方陈述，带姓名、电话、订单号，属于个人信息；入库前必须脱敏，报告里单列一章、注明「消费者单方陈述」。

## 二、官方来源清单（第一档，先接这些）

| 来源 | 能拿到什么 | 更新频率 | 稳定性风险 |
|---|---|---|---|
| 各地市监局「行政处罚公示」 | 处罚决定书文号、当事人、违法事实、处罚结果、公示日期 | 不定期 | 各地页面结构不统一，会改版 → 每个来源一个适配器 + 改版监控 |
| 食品抽检不合格通报 | 样品名称、被抽样单位、不合格项目、检验机构 | 按批次 | 多为 PDF/附件，需解析 |
| 信用中国 | 行政处罚、经营异常、失信名单 | 持续 | 有查询接口，注意频率限制 |
| 国家企业信用信息公示系统 | 主体信息、行政处罚、经营异常 | 持续 | 有验证码/风控，做限速与重试 |
| 裁判文书网 / 执行信息公开网 | 案号、案由、审理法院、裁判结果 | 持续 | 检索有门槛，按主体名精确查 |

接入顺序：先接 1–2 个市监处罚公示源跑通全链路，再按同一套适配器接口扩。

**主体风险当前使用的来源：越秀区「双公示 · 行政处罚」**（`backend/app/collectors/yuexiu_sgs.py`）。区政府门户提供纯 JSON 接口，一份决定书一条记录，23 个结构化字段（企业全名、统一社会信用代码、文号、违法事实、处罚依据、处罚内容、罚款金额等），程序可直接访问；演示库入库 235 条餐饮处罚、217 个主体。接口细节见根目录《越秀区双公示_接口说明.md》。礼貌采集（请求间固定间隔），列表先按名称筛餐饮候选、只对这些取详情。

广州市监局、深圳市监局的典型案例来源也已接入，见第六节；其匿名化主体不用于主体排名。

## 三、每条内容必须具备的字段

| 字段 | 含义 | 示例 | 缺失时怎么办 |
|---|---|---|---|
| `source_category` | 来源类别 | 官方通报 / 媒体报道 / 顾客投诉 | 必填，不允许为空 |
| `official_url` | 官方原文链接 | `https://.../处罚决定书` | 官方通报缺失 → **不入库** |
| `published_at` | 官方发布日期 | 2026-11-12 | 用抓取时间并标注 |
| `store_subject` | 涉事门店主体（不是品牌） | 香满园·幸福路店 | 缺失 → 报告标「主体待核实」 |
| `investigation_status` | 调查状态 | 立案 / 责令整改 / 已处罚 / 已结案 | 缺失 → 标「状态待核实」，不猜 |
| `handling_result` | 处理结果 | 罚款 5000 元、没收违法所得 | 缺失 → 留空，不写结论 |
| `evidence_snapshot` | 页面快照路径 | `evidence/2026/11/xxx.html` | 官方通报必存 |
| `content_hash` | 快照内容的 SHA-256 | `a3f1...` | 官方通报必存，用于自证未篡改 |
| `fetched_at` | 抓取时间 | 2026-11-22 23:40 | 必填 |

补充规则：

- **调查状态不等于违法认定。** 「立案」「责令整改」只是程序状态，报告里不得写成「违法」「被罚」。
- **门店主体优先于品牌。** 总部要看的是「哪家店、直营还是加盟、在哪个区域」，品牌级汇总只是报表的一层。
- **投诉按每百店折算。** 不做跨品牌总量对比，总量会被门店数带偏。

## 四、证据留存

官方来源每条都存三样：页面快照、内容 hash、抓取时间。目的只有一个——报告被质疑时能自证「当时页面上就是这么写的」。
当前实现按内容 SHA-256 去重，默认路径为 `backend/data/snapshots/<hash前两位>/<hash>.html`（可由 `YUQING_SNAPSHOT_DIR` 修改）。`source_snapshot` 保存 hash、原文 URL、来源、路径和抓取时间，`official_record.snapshot_sha256` 引用它；读取时重新计算 hash，校验失败视为快照不可用。扩展名统一为 `.html`，越秀详情快照保存的实际内容是 JSON 字节。

## 五、脱敏

以下是未来接入真实投诉数据的要求；当前没有真实投诉采集入口，不能据此声称已有通用脱敏流水线：

- 手机号、身份证号、订单号、住址 → 掩码（保留末四位）
- 投诉人姓名 → 「某先生/某女士」
- 只保留与事件判断有关的文本，原图原视频不落库

## 六、演示数据怎么来

面试演示涉及三组数据，存储和用途分开：

| 数据 | 位置 / 来源 | 数量与用途 |
|---|---|---|
| 模拟舆情 | `backend/app/engine/seed_data.json` → `content` 等舆情表 | 虚构品牌「香满园」8 批次，演示时钟、评级、预警、处置、事件报告 |
| 真实典型案例种子 | `backend/app/engine/official_seed.json` → `official_record` | 54 条：广州市监局 `gz_amr` 43 条、深圳市监局 `sz_amr` 11 条；逐条带官方链接与快照 hash，官方已匿名化的主体保持原样 |
| 越秀双公示采集记录 | 采集器 `collectors/yuexiu_sgs.py` → 正式业务库 `official_record`，`source_id=yx_sgs` | 当前演示基线 235 条、217 个主体，支持 `/subjects` 区域画像、排名和体检报告；不在上述种子文件中 |

种子加载按 `record_key` 幂等补入，不会凭空生成越秀记录。新建空库仅有种子文件不能复现 235 条的主体风险演示；需另行采集越秀来源，或恢复已备份的记录及其对应快照。官方记录引用 `source_snapshot`，快照文件默认在 `backend/data/snapshots/`。

主体风险当前只读取带企业全名的 `yx_sgs` 餐饮记录；脱敏的广深典型案例不进入主体排名。模拟舆情与官方处罚分别存储、分别评分，不能把它们当作同一批数据。

## 七、主体风险评分（第③④步）

以营业执照主体（统一社会信用代码）为单位，给官方处罚记录打分排名，评分规则沿用门店评分、不为了演示改规则：

| 档位 | 基础分 | 判定 |
|---|---|---|
| 移送公安 | 50 | 调查状态是「公安已立案/已移送公安」或处理结果写了移送公安 |
| 罚没处罚 | 30 | 处理结果有罚款（不含「拟罚款」）或没收；按金额另加 0–15 分 |
| 立案调查 | 20 | 只写了立案、还没有处理结果 |
| 警告/责令整改 | 10 | 只有警告、责令改正 |

- 罚款加分 = min(15, max(0, 5 × log10(金额 / 1000)))，按一位小数计；金额缺失或低于 1000 元不加分。吊销许可证 / 责令停业另加 10 分。
- 时间衰减：官方记录半衰期 365 天。评分引擎读取 `published_at`；典型案例使用公告发布日期，越秀双公示将处罚决定日期 `cfJdrq` 同时写入 `published_at` 和 `decided_at`，因为该源没有独立发布日期。`data_until` 取所选来源记录中最大的 `published_at`，所以越秀页面的「数据截止」实际是最近处罚决定日期，不是抓取时间或独立的公示日期。`as_of` 是计算时间衰减的评估日期；前端默认 `2026-11-23`，后端不传时按当天。 当前日期早于记录日期时衰减系数按 1，不按 `as_of` 排除未来记录；这是评分参考日，不是历史数据截面。
- 主体分 = round(min(逐条衰减得分合计, 70))；等级 ≥60 高、≥30 中、>0 低、0 无。排名先按未封顶合计分降序，再按记录数降序、主体键升序，同为 70 分也可能名次不同。
- **投诉不计分**：没有合规公开的投诉来源，不编数据，报告里明写原因。
- **违法类别**（食品安全 / 消防 / 市容 / 烟草 / 登记证照 / 广告商标价格 / 劳动用工 / 文化 / 其他）不改变单条记录的评分规则；「只看食品安全」先筛出该类别记录再汇总，因此排名分会变化。单主体体检报告仍使用综合口径，并另列食品安全排名。
